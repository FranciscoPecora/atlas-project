# Decisions

One line per design choice: decision, reason, alternative rejected.

- 2026-11-16 · ISW collection waits for written permission (collector refuses while `collect.isw.enabled` is false) · ISW's fair-use policy requires prior written permission to incorporate its material into datasets or maps · rejected: collect now and ask later.
- 2026-11-16 · No automated access through Cloudflare blocks; criticalthreats.org mirror dropped · both hosts block scripted requests, and getting around bot checks is off the table · rejected: browser-like user agent or headless browser.
- 2026-11-16 · Gold sampling unit is one of 7 heading-defined sectors, assigned by ordered keyword rules · ISW has no per-direction headings and its heading wording changed between July and November 2026 · rejected: splitting on "X direction" phrases (segmentation errors would leak into the gold set).
- 2026-11-16 · Empty container headings are skipped and absorbed into the next unit · July's "Russian Main Effort: Eastern Ukraine" has no body and spans three sectors · rejected: treating it as UNMAPPED.
- 2026-11-16 · GSU report = ArmyInform post whose body states "оперативн… інформаці… станом на 8:00", candidates ranked by slug keywords · slugs vary by day; a `genshtab-zsu` suffix filter found 0 of 3 test days · rejected: slug-only selection; WordPress REST API (disallowed by robots.txt).
- 2026-11-16 · Gold label files store offsets and the text SHA-256, not quotes · test labels are committed, and source text must never be committed · rejected: storing `evidence_quote` in gold.
- 2026-11-16 · Confirmation lag (rule 7b) is measured between report dates · the question is when confirmation became available · rejected: event dates (footage often shows earlier events).
- 2026-11-16 · Two models: `ExtractedEvent` (model output, `extra="forbid"`) and `LedgerEvent` (adds code-computed fields) · the model must not be able to return offsets or coordinates · rejected: one model with optional offset and coordinate fields.
- 2026-11-16 · `quantity` may match a number word (SPEC Appendix C) · GSU and ISW often write small numbers as words · rejected: digits only (would reject correct records).
- 2026-11-16 · `gliner2` installed in milestone 2, not at setup · it pulls in PyTorch (about 1 GB) and only baseline B1 uses it.
- 2026-11-17 · Ukrainian dev reports get an English reading aid from Claude (`models.translation`, src/translate.py), shown beside the Ukrainian in Label Studio; the Ukrainian stays the labelled text · the annotator reads no Ukrainian and web translators cap input length · rejected: an offline translator such as Argos (independent of Claude, but slower to set up; the user chose speed), and labelling an English translation (offsets would not point into the source). Risk: the aid can carry Claude's reading of the text into dev gold labels. Test-split reports are refused in code (SPEC.md section 4: never labelled from model output); how to read the 12 Ukrainian test reports is still open.
- 2026-11-17 · General Staff dev tasks are pre-filled by rules (src/prelabel.py, no model): one ground_assault per place per paragraph, direction-level events where no place is named; the annotator checks every proposal · hand-labelling about 50 events per GSU report was too much work for one annotator · rejected: Claude pre-labels (would share the extractor's errors), labelling fewer GSU units (needs a SPEC amendment; still open). Anchoring is measured, not assumed: a CONTROL task (two paragraphs of one dev report, set in config.yaml) is labelled from scratch first and compared with the checked pre-fill (src/prelabel_check.py, target F1 0.9 in config.yaml). Test units are never pre-filled unless SPEC.md is amended first.
- 2026-11-17 · General Staff dev key is machine-made: rule pre-fills, then a reviewer model (`models.gold_review`, src/review.py) keeps, fixes, removes or adds events under the guideline; code computes offsets and rejects events whose quote, place or quantity is not in the text; the annotator spot-checks 30 random events and 10 random paragraphs in English (src/audit.py, limit 5% each) · the annotator reads no Ukrainian and found checking about 170 pre-fills too much · rejected: no human check at all (scores would only mean agreement with another program), a second vendor's model as reviewer (still a model; adds a dependency and a key). Risks, stated in the README: reviewer and extractor are one model family (correlated errors), B0 shares the pre-fill's patterns, the audit reads a machine translation. Dev only: test units are refused in code until draft amendment A1 is approved. The Label Studio control task and src/prelabel_check.py stay as the fallback path. Hard cases 7 and 9 to 12 got provisional rulings so the reviewer applies one convention.
- 2026-11-17 · Amendment A1 approved and recorded in SPEC.md: GSU gold (dev and test) is rules + reviewer + sampled human audit · owner's decision after seeing the dev key · open for milestone 2: src/review.py, src/translate.py and src/audit.py still refuse test units; enabling them must not break the rule that only eval/score.py opens eval/gold/test/, so the test audit page has to be built in the same run that writes the test key, from memory, not by re-reading the files.
- 2026-11-17 · Audit round 1 of the GSU dev key is void and kept on record (eval/audit/*_round1.json: 8 of 10 judged events wrong, 9 of 10 paragraphs missing, every note "missing count") · the page never said that a count shared by several places is left empty on purpose (SPEC 2.1 one event per place; hard case 9), so the annotator marked correct events wrong; the annotator confirmed the events were otherwise correct · round 2 uses a fresh seeded sample (`audit.round` in config.yaml) and a page that states the rule on every such event · rejected: re-reading round 1 answers as Right (the auditor's verdicts are not mine to change), and giving every village the direction total (it would state a number the source does not give for that place).
- 2026-11-17 · Audit round 2 accepts the GSU dev key under amendment A1: 1 of 30 events wrong (3.3%, 95% Wilson interval 0.6% to 16.7%), 0 of 9 judged paragraphs missing something (0%, interval 0% to 29.9%), 1 paragraph not sure (eval/audit/dev_answers_round2.json) · both point estimates are within the 5% limit; the intervals are wide because the sample is 30 and 10 · the one Wrong and the one Not sure are the same paragraph of the 21 July report: Ukrainian strikes with counts and no place, which the reviewer wrote as three `other` events (hard case 11, provisional). Left as the reviewer wrote it until the owner rules on hard case 11; it is the only such sentence in the three dev reports.
- 2026-11-17 · Hard case 11 confirmed by the owner: Ukrainian strikes with a count and no place stay as one `other` event per kind of target, with no location · it is a distinct claim in the source · rejected: not an event (my recommendation; such events can never match on location). The audit verdict Wrong on that event stays on record.
- 2026-11-17 · Gazetteer = GeoNames UA (populated places and admin areas) plus OSM place nodes fetched through Overpass, merged when a name is shared within 5 km; ids `gn:<id>` and `osm:<id>` · the full Geofabrik extract is about 800 MB and needs a new library to read; a place-node query gives the same names in 19 MB with no dependency · rejected: the pbf extract. Limit: no Russian places yet (the Kursk direction resolves to a namesake near Sumy); the RU_INTERIOR sector will need the GeoNames RU dump.
- 2026-11-17 · Same-named places are chosen by distance to the town the paragraph's front direction is named after (`geocode.direction_anchors` in config.yaml), and refused beyond `max_anchor_km` · Ukrainian has many namesakes (Yasne, Yampil, Oleksandrivka) and population alone picked the wrong oblast · rejected: population only. The Slobozhanskyi, Kursk and Oleksandrivka anchors are approximate. Lookup strips case endings ("Ясного" = "Ясне") before fuzzy matching.
- 2026-11-17 · "Resolved" in the 30-name dev check means a row was returned within the distance limit, not that a person confirmed the row; 30 of 30 resolved, and I read all 30 against the English glossary and found none in the wrong region.
- 2026-11-17 · `gliner2[local]` added (pulls PyTorch and transformers, about 2 GB with the two models) · baseline B1 in SPEC.md section 6 is defined on GLiNER2 · rejected: skipping B1. Plus `sentencepiece` and `protobuf`, which the multilingual tokenizer needs.
- 2026-11-17 · B0 for General Staff reports reuses the pre-fill patterns of src/prelabel.py; B1 uses GLiNER2 settlements with keyword rules for the type · SPEC section 6 defines both only in one line · consequence, stated wherever B0 is reported: the GSU key started from the same patterns, so B0's dev F1 (0.975) is circular and not a fair baseline. SPEC 5.1 ambiguity noted: an event whose named place does not geocode is treated as having no location.
- 2026-11-17 · GSU corpus: 108 of 120 days collected; 12 days have no post stating the 08:00 cutoff (2, 3, 16, 22, 23, 24, 30 August; 2, 5, 12, 18, 24 October) and are logged as missing in data/manifest.csv · those days' posts say "as of Saturday, 22 August" with no hour, which is outside SPEC section 1's definition of a report · the cutoff pattern was widened only to allow words between "оперативн… інформаці…" and "станом на 8:00", which recovered 36 days. Rejected for now: accepting posts without the hour (would change the definition of a report after seeing the data).
- 2026-11-17 · Test units gsu-2026-08-22 and gsu-2026-08-30 are replaced by 2026-08-25 and 2026-08-31 under SPEC 4.1 (next available date), pinned in config.yaml `gold.substitutions` · the owner chose the pre-registered rule over amending the SPEC or dropping the units.
